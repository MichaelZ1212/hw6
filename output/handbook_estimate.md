# Handbook cost estimate

How much does it cost to send `data/shop_handbook.md` to **gpt-6-luna** on every call?
Generated by `scripts/handbook_estimate.py`.

## 1. Size of the handbook

| Measure | Value |
|---|---:|
| Characters | 28,903 |
| Words | 6,127 |
| Lines | 338 |
| **Tokens (o200k_base)** | **10,058** |

**How the tokens were counted:** the whole file was read as UTF-8 text and encoded with
`tiktoken`'s `o200k_base` tokenizer, the encoding used by OpenAI's current GPT models,
then the tokens were counted. That works out to 2.9 characters per token.
The usual rule of thumb of about 4 characters per token would give only 7,226 tokens.
The handbook packs denser than plain prose because it is full of SKU codes, prices, numbers,
tables, and Markdown symbols, which split into many short tokens. When the handbook goes out as a
system message, the API adds a few formatting tokens, so the billed number will be slightly higher.

## 2. Prices (gpt-6-luna, from `data/prices.json`)

| Price type | Per 1M tokens | Per token |
|---|---:|---:|
| Input (not cached) | $0.1 | $0.000000100 |
| Cache write (first time the prefix is stored) | $0.125 | $0.000000125 |
| Cached input (cache hit) | $0.01 | $0.000000010 |
| Output | $0.5 | $0.000000500 |

Only the handbook's input tokens are priced here. The vendor document and the model's answer
are extra and change from call to call.

## 3. Cost of the handbook alone

### Without caching (every call pays full input price)

- 1 call: 10,058 x $0.1 / 1,000,000 = **$0.001006**
- 1,000 calls: $0.001006 x 1,000 = **$1.0058**

### With caching (first call writes the cache, the rest read it)

- 1st call (cache write): 10,058 x $0.125 / 1,000,000 = **$0.001257**
- Each later call (cache hit): 10,058 x $0.01 / 1,000,000 = **$0.000101**
- 1,000 calls: $0.001257 + 999 x $0.000101 = **$0.1017**

### Side by side

| Scenario | 1 call | 1,000 calls |
|---|---:|---:|
| No caching | $0.001006 | $1.0058 |
| With caching | $0.001257 (write) / $0.000101 (hit) | $0.1017 |
| **Savings** | | **$0.9041 (89.9%)** |

## 4. What caching saves

- A single cached call is a bit **more** expensive than an uncached one
  ($0.001257 vs $0.001006), because storing the cache costs
  $0.125/1M instead of $0.1/1M.
- Every later call that hits the cache pays $0.01/1M instead of
  $0.1/1M, which is **90% cheaper**.
- Caching pays for itself from the 2nd call on. Over 1,000 calls the handbook bill drops from
  $1.0058 to $0.1017, about **9.9x cheaper**.
- In dollars the numbers are small because gpt-6-luna is cheap. The pattern still matters,
  because the handbook is sent on every call, so it makes up most of the input tokens.

**Assumptions to check against real usage later:**
1. The handbook is placed first in the prompt and never changes, so every call shares the same prefix.
2. Calls come close enough together that the cache stays warm. If the cache expires, the next call
   pays the write price again.
3. The billed token count will be a little above 10,058 because of message formatting tokens.
   The real API response (`usage.prompt_tokens` and `cached_tokens`) is the number to compare against.
